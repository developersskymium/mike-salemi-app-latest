# Spec 02 — Training engine package (`packages/core`)

Owner: engine agent (Opus medium). Lead reviews and merges.

## Goal
A platform-neutral TypeScript package holding every training rule, so the web app now and the phone apps later behave identically. The database enforces the same rules (see `supabase/migrations/0004_functions.sql`); this package lets the UI predict and render them instantly and is the place the rules are tested.

## Constraints
- Pure TypeScript. No React, DOM, Node-only APIs or Supabase client. Inputs are plain data shaped like `src/types.ts` (extend that file if needed; don't rename existing fields without telling the lead).
- Tests with Vitest in `packages/core/src/**/*.test.ts`. `pnpm --filter @ms/core test` must pass.
- Legacy app source for reference (read-only): `/home/claude/legacy/src`. Port behaviour, not code style.

## Modules to write (one file each, exported from `src/index.ts`)
1. `readiness.ts` — `scoreForm(form, answers)`, `isFormComplete(form, answers)`, `resolveOutcome(form, score)` with the exact SQL semantics: first band (by `position`) whose `[minScore, maxScore]` contains the score; otherwise `{ name: 'Full Workout', band: 'green', outcome: 'workout', tableId: form.defaultTableId, message: '' }`. Also `bandsFromGravityRules(rules, maxScore)`: converts legacy Gravity-Forms rule logic (operators `is`, `isnot`, `>`, `<`, `>=`, `<=`, `greater_than`, `less_than`, logicType all/any — see legacy `src/content/kbl-forms.ts` `matchesRule`) into contiguous inclusive ranges by enumerating integer scores 0..maxScore (a rule covering non-contiguous scores becomes several bands). Test: for every legacy form (`/home/claude/legacy/src/content/source-readiness.json`) and every one of the 108 answer combinations, `resolveOutcome(converted form, scoreForm(...))` equals the legacy resolver's band name + table id (import the legacy fixtures in `/home/claude/legacy/src/lib/__fixtures__/` if helpful, and read the legacy tests `kbl-readiness.test.ts`, `kbl-forms.test.ts` to mirror their assertions, including the approved corrections: tired=yes → 15 points; forms 25/26/27 default to tables 29/33/39). Copy the needed legacy JSON into `packages/core/src/__fixtures__/` so tests don't depend on /home/claude/legacy at runtime.
2. `progression.ts` — given an ordered `Curriculum` and `CompletedSteps`: `lessonProgress`, `isLessonComplete` (all required steps done), `openThrough(steps, completed)` (index of first incomplete required step), `isStepOpen`, `isLessonUnlocked(curriculum, lessonId, completed, lockedOrder)` (when locked: every earlier lesson in curriculum order complete — identical to SQL `private.lesson_unlocked`), `currentLesson` (first incomplete lesson; null when all done), `sectionProgress`, `pathProgress` (percent by steps and by training days, overview/transition pages excluded from day counters but included in completion — as legacy `docs/kbl-course-parity.md` describes), `milestonesFor(curriculum, completedBefore, completedAfter)` → which of lesson / section / path just completed. Port the legacy logic in `src/hooks/use-progress.ts` (`summarise`, `dayUnlocked`), `src/lib/milestones.ts`, and the step locking in `src/routes/_authenticated/immersion.day.$dayId.tsx` (`unlockedThrough`, `isUnlocked`). Tests including the legacy parity cases (`kbl-parity.test.tsx` intent: independent level starts, completion boundaries).
3. `playlist.ts` — port `src/lib/stage-playlist.ts` (+ its test) to the new `Step`/`VideoRef` shape: lesson video then clips, skip a clip duplicating the lesson video, `nextClip`, `playingClipId`. Also `WATCHED_RATIO = 0.95` and `isWatched(seconds, duration)`.
4. `next.ts` — port `src/lib/whats-next.ts` `recommendNext` (end-of-day guidance using next lesson + today's readiness band + days left in section), generalised to any day program; return plain data (labels + target lesson id), no routes.
5. `schedule.ts` — Immersion "Scheduled pace" and Self-Guided calendars: `placeLessons({ lessons, startDate, trainingDays, done })` → dated entries; `applyMissedDayRule(entries, today, rule: 'shift'|'skip'|'weekend')` matching the legacy behaviour in `src/routes/_authenticated/schedule.index.tsx` and `src/lib/schedule-sync.ts` (+ port `schedule-sync.test.ts`). Dates as `YYYY-MM-DD` strings; no timezone surprises (tests across DST).
6. `workout-export.ts` — port `src/lib/workout-export.ts` (+ test): CSV with circuit breaks, notes, rest arrows, UTF-8 BOM.
7. `vimeo.ts` — `parseVimeo(input)` → `{ providerId, privacyHash }` from ids like `"400475380/bd283c1aa1"`, full URLs, player URLs; `embedUrl(ref, opts)`; port relevant bits of `src/lib/vimeo.ts`.
8. `pricing.ts` — `resolvePrice({ programId, basePrices, planId, benefits, owned })` → `{ state: AccessState, amountCents, discountPercent, label }` implementing: included → no price; discount → best price; never stack; owned → no price. Plus `planRankOk(benefitsByPlan)` asserting higher plans never get worse benefits. Tests.
9. `mtk.ts` — port `src/lib/mtk-paths.ts` and `src/lib/mtk-plan.ts` (+ tests) to work from plain lesson data (copy `src/content/mtk-lesson-meta.json` into the package).
